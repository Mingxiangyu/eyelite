## 截图

`docs/screenshots/` 全部由 `tools/shoot.py` 生成（`ctypes` + 标准库 `zlib` 手写 PNG，不依赖 PIL）。

```
python tools/shoot.py docs/screenshots              # 全部：界面 3 张 + 9 个动作
python tools/shoot.py docs/screenshots action       # 只重拍名字含 action 的（9 个动作）
python tools/shoot.py docs/screenshots settings     # 只重拍设置页
```

命名规则：`action-<英文名>.png` 为动作演示，`settings.png` / `rest-overlay.png` / `02-preview.png` 为界面。
`dual-monitor.jpg` 是早期手工截图，保留作为多屏参考。

三条必须知道的：
1. **脚本会整份覆盖 `config.ini`**，跑完按**原始字节还原**（`finally` 里做，异常也不丢配置）。
2. 动作截图靠 `EYE_LITE_FAKE_ACTION=<动作名>` 让程序启动就只播那一个动作；
   没有这个钩子只能靠久坐节奏轮换，一次拍不到 9 个。
3. 截图只用 `PrintWindow`，**绝不截屏** —— 截屏会把用户桌面上的其它窗口拍进公开仓库
   （本会话真踩过：抓到过一次 WorkBuddy 窗口，图已删、代码路径已删）。

## 三类"以后别再查"的结论

这三条在文档里反复出现过，集中放这里：

1. **"倒计时刷新被卡住"不成立。** 五个版本、97 个 `P` 间隔，最大 1029ms，无一 ≥2000ms。
   用户看到的"卡住"是**横幅被收掉**（`c518841` 已修）。详见 `qa/preview-skip-findings.md` §0。
2. **单实例互斥是写死的字符串**（`EyeLite_SingleInstance_v1`），与文件名无关。
   "改 exe 名字能并行跑测试"是**错的**——曾据此误判过一次。
3. **抓图脚本必须自己声明 DPI 感知**（`SetProcessDpiAwareness(2)`），否则 `GetWindowRect`
   返回虚拟化坐标，`PrintWindow` 只抓到左上角一小块。这个坑骗过至少三个人次。

## 两条"已经拍过板、别再摇摆"的取舍

1. **A2「休息前渐暗」默认关闭**（`DimAlphaMax` 默认 0）。它每次写 `Opacity` 都让 DWM
   重合成整屏，实测把"60±3 秒到点"拖到 62~63 秒。**判据不动，改产品** ——
   "准时"是核心承诺，渐暗是美化层。要复现这条结论就跑 `tools/p0a-timing-check.py`，
   分别在 `DimAlphaMax=45` 和 `=0` 下各 5 轮。
2. **毒舌语气只对行为/场景开火，不对身体和人格开火**。这是「不做健康诊断」这条立场的
   直接推论：说「椅子快和你长一起了」可以，说「你这腰再坐下去就废了」不可以。
   改文案时先回看 `AppConfig.Tone` 上的两条硬约束。
