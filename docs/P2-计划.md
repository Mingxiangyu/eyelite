## 一、建议做（4 项）

### 1. 会议检测（原 C2 + D4）—— ✅ 已实现（2026-11-15），A 项已验证

**做什么**：检测到会议进行中（Zoom / Teams / 腾讯会议 / 飞书）时，**不弹遮罩**，
但账单照记（归 `Deferred`），会议结束后再提醒。

**怎么判**：进程名白名单 + 该进程是否有可见窗口（判断"是否真的在会中"，而不是只开着的客户端）。
麦克风占用作为补充信号（`IAudioSessionManager2` 枚举录音会话）。

**怎么验收**：
- 对照组：只开客户端不开会 → 仍然正常提醒（重要，避免"装了开会软件就再也不提醒"）
- 实验组：真正在会中 → 不弹；散会后 ≤60s 内补提醒
- 账单：会议时段归 `Deferred`，不丢也不计入用眼

**风险**：误判成"一直在开会"= 永不提醒（与 §10.1 同一类错误）。
**建议**：用**进程 + 可见窗口**双条件，且抑制上限沿用 30 分钟强制放行。不要只听麦克风——
浏览器标签里的任何网页都可能占麦。

---

### 2. 沉浸模式（原 Immersion）—— ✅ 已实现（2026-11-15），待 P0 回归

**做什么**：用户手动开启后，**只保留托盘进度环**，不弹任何遮罩/横幅/渐暗。

**为什么值得做**：这是"我知道我在干嘛，别烦我"的显式表达。
现在用户只能"暂停计时"，而暂停**不记账**；沉浸模式应该**继续记账**。

**怎么验收**：
- 开启后 60 秒内无任何窗口出现（含 DimForm、EdgeGlow）
- 账单继续累计（时长不会被"沉浸"吃掉）
- 关闭后立刻恢复正常行为，且不补弹历史欠账（只从当前余量继续）

**风险**：低。本质是一个"只算不弹"的开关。
**建议**：放在托盘菜单，与「暂停计时」并列，文案要区分清楚：
暂停 = 不记账；沉浸 = 记账但不打扰。

---

### 3. 动作库扩充（原 B3 / B4 / G4）

**做什么**：再补 3~4 个久坐动作，重点是**零位移、办公室能做的**：
- 「肩胛后缩」：只动肩，坐姿可做
- 「坐姿转体」：椅子上的躯干旋转
- 「踝泵」：脚下踩踏板，促进下肢回流（久坐最实用）
- 「找东西」：眼睛找房间里的 3 样蓝色物体（属护眼休息，需重新考虑挂载点）

**怎么验收**：每个动作要能被 `G11` 禁忌词正确排除；`p1-batch23 movement` 6/6 仍绿。

**风险**：低（纯数据）。唯一要小心的是**禁忌词不能乱写**——
写多了会让有该问题的人白丢一个可用动作。
**建议**：只做前三个（都是坐姿可做），第四个「找东西」需要先决定它挂在哪一类休息上。

---

### 4. 打包与分发

**做什么**：产出可直接分发的 zip（exe + README + 一份最小配置说明），
并给 `build.cmd` 加一个 `release` 分支：编译 + 干净打包 + 打印指纹。

**为什么现在做**：拖到最后一定会忘。而"怎么装、装到哪、要不要管理员"这些事，
应该在代码还热的时候写下来。

**怎么验收**：解压到空目录 → 双击能跑 → 配置写在 `%APPDATA%` → 卸载只需删目录 + 删自启项。

**风险**：低。
**建议**：**先做这个**，成本最低，收益是"别人（或半年后的你）能装起来"。

## 拍板结果（2026-11-15）

| 问题 | 决定 |
|---|---|
| 沉浸模式与暂停的关系 | **暂停 = 不记账；沉浸 = 记账但不打扰** |
| 会议检测的抑制上限 | **沿用 30 分钟强制放行** |
| 「找东西」挂在哪 | **普通护眼休息** |

### 沉浸模式已落地

配置 `Immersive`；托盘菜单「沉浸模式（照常计时，不打扰）」；托盘文案改为静态"沉浸模式 · 照常计时，不打扰"。

实现位置：tick 里在 gate 与"让路"之后、预告/到点/统计之前早退 —— 累加器已经走完，
所以时间不丢。开启时立刻收掉已挂着的载体（遮罩/预告/压暗/辉光/仪式窗），
否则"点完菜单还看着一块全屏遮罩"就不叫沉浸。

**已验证**：`python tools/p2-immersive-check.py` → 75 秒（WorkMinutes=1，本该 60 秒到点）
零窗口、进程存活 → PASS。
**未验证**：「照常计时」这半句无法外部观测（累加器在进程内，换配置要重启），
只有源码审查结论 —— 脚本里也如实标注了这一点。
对照组（关沉浸应能看到遮罩）默认不跑，会弹 8 秒全屏；加 `--with-control` 才跑。


### 会议检测已落地

判据：**进程白名单 + 该进程有可见窗口 + 窗口标题命中关键词**，三条同时成立。
- 只看进程 → 装了客户端的人"永不提醒"，正是 §10.1 的"坏掉的版本"
- 只看标题 → 聊天窗口里出现"会议"两个字也会误判，所以进程先过一遍
- fail-open：取不到进程名/标题一律当作"不在会中"

复用现有「抑制 + 30 分钟强制放行」：只是给 `blocked` 多一个来源，
不另造状态机（两套抑制逻辑并存是 bug 的温床）。账单照旧归 `Deferred`。

配置：`MeetingGuardEnabled`（默认开）、`MeetingProcesses`、`MeetingTitleKeywords`。

**已验证**：`p2-meeting-check.py` A 项 —— 在会中 75 秒（WorkMinutes=1）零窗口 → PASS。
**待验证**：B（不在会中应照常提醒）、C（关掉开关应照常提醒）—— 两条都会弹 8 秒全屏，
默认不跑，需 `--with-control`，等用户离开时补。
**测试钩子**：`EYE_LITE_FAKE_MEETING=1/0` 强制入会信号，未设走真实检测。


### 「找东西」已落地（2026-11-15）

挂**普通护眼休息**：遮罩主提示改为
「让眼睛离开屏幕：看看 6 米外，或在房间里找 3 样蓝色的东西」。配置 `EyeGameEnabled`（默认开）。

两处刻意不做：
1. **不做屏幕动画**：护眼休息要眼睛离开屏幕，动画等于把视线钉回来（与仪式窗只挂久坐休息同一个理由）。
2. **不做每轮轮换**：我先写了轮换版，实测 3 轮拿到 `0/0/1`（会跳拍），没能定位。
   行为不明的功能不发布，退回一句固定文案 —— 需求是"挂到普通护眼休息"，不是"必须轮换"。

**已实测**：遮罩文案确实变为上面这句（按 pid 过滤枚举子窗口文本）。

### 会议检测的内存代价：25.0MB → 18.6MB

第一版用 `System.Diagnostics.Process.GetProcessById` 取进程名，实测私有内存从 17.8 涨到 **25.0MB**
（+7.2MB，GDI 不变）。为一个"只在到点前才需要"的判断付 7MB 不划算，
改用 `QueryFullProcessImageName`（纯 P/Invoke）后降到 **18.6MB**（净 +0.9MB）。
