# 严格模式 / 遮罩：按键与计时用例

本清单描述**每种配置下用户应当看到的行为**，用于休息遮罩、键盘屏蔽与计时一致性的人工回归。

## 编号命名空间

本仓库有两份文档会互相引用，各自独立编号时会产生同名不同义。约定如下，**引用时一律带命名空间**：

| 前缀 | 属于 | 权威文档 | 示例 |
|---|---|---|---|
| `A*` / `B*` / `C*` | 休息遮罩按键 / 计时一致性 / 已知限制 | **本文** | `用例库-B7` |
| `R1`–`R4` | 运行模式（配置档，不是用例） | 本文 | `模式 R1` |
| `M1`–`M8` | 会议检测 | 会议检测规格（PRD §8） | `PRD §8-M5` |

「B7」在本文指「跳过后下一个工作周期」，在 PRD 里曾是另一件事（会中卸载插件）——后者已改号到 `M*`。看到裸编号而无法判断归属时，先问是哪份文档，不要猜。

## 阅读前提

遮罩窗体不获取键盘焦点（`WS_EX_NOACTIVATE`），因此休息期间的所有按键行为都由全局键盘钩子决定，与窗体焦点无关。**不声明运行模式的用例无法判定结果**——同一条用例在下面四种模式下结论可能相反。

### 运行模式

| 模式 | 允许跳过 | 严格模式 | 键盘行为 |
|---|---|---|---|
| **R1**（默认） | 是 | 是 | 所有按键不生效；裸 Esc / 裸 空格 = 跳过 |
| **R2** | 是 | 否 | 仅裸 Esc / 裸 空格 被拦截用于跳过，其余按键正常输入 |
| **R3** | 否 | 是 | 拦截 Win / Alt+Tab / Alt+F4 / Ctrl+Esc，其余按键正常输入 |
| **R4** | 否 | 否 | 不安装钩子，键盘完全正常 |

「裸按键」指不按任何修饰键（Ctrl / Alt / Shift 均未按下）。Shift+Space、Ctrl+Space、Alt+Space、Shift+Esc 都不视为跳过。

## 测试前准备

**默认「工作 20 分钟」下，单条用例就要等 20 分钟——等于不会被执行。** 除 B5 外，本清单所有条目都能在 5 分钟内跑完，前提是先改参数：

| 参数 | 建议值 | 说明 |
|---|---|---|
| 工作时长 | **1 分钟** | 快速制造休息；涉及锁屏的 B1/B2 用 **5 分钟**，否则休息会在锁屏过程中到期 |
| 休息时长 | **20 秒** | 快速跑完整轮 |
| 离开多久后暂停 | **1 分钟** | 涉及离开判定的条目不设 1 分钟的话，单条要等 3 分钟才触发 |
| 允许跳过 / 严格模式 | 开 / 开 | 即模式 R1，除标注 R2–R4 的条目外都用它 |

**B5 是唯一无法实测的条目**（需要跨 49.7 天回绕），只保留源码级结论，不要为它安排跑测时间。

## A 组：休息遮罩期间的按键行为

| ID | 模式 | 步骤 | 预期 |
|---|---|---|---|
| A1 | R1 / R2 / R3 | 按 Alt+Space | 不结束休息；R1 下窗口系统菜单也不出现 |
| A2a | R1 / R2 | 按 Ctrl+Space | 不结束休息 |
| A2b | R1 / R2 | 按 Shift+Space | 不结束休息（避免与输入法全角/半角切换冲突） |
| A2c | R1 / R2 | 按 Shift+Esc | 不结束休息 |
| A3 | R1 / R2 | 按住空格 3 秒 | 只跳过**一次**，不因按键自动重复而连续触发 |
| A3b | R1 / R2 | 承 A3，观察跳过之后 1 秒内继续按键 | 按键**不得**输入到下层程序（跳过瞬间仍按住的键，其重复消息必须被拦截，直到物理抬起） |
| A4 | R1 / R2 | 按裸空格 | 结束休息，且只结束一次 |
| A4b | R1 / R2 | 按裸 Esc | 结束休息（与空格等效） |
| A5 | R3 / R4 | 按裸 Esc | **不**结束休息（该模式未开启跳过） |
| A6 | R1 | 按 Alt+F4 | 遮罩不消失，进程不退出 |
| A6 | R3 | 按 Alt+F4 | 遮罩不消失 |
| A6 | R2 | 按 Alt+F4 | 遮罩不消失（按键落到用户自己的前台窗口，该窗口可能被关闭，属该模式的合理代价） |
| A7a | R1 | 按 Alt+Tab / Ctrl+Esc | 无法切换窗口，遮罩保持最前 |
| A7b | R2 | 按 Alt+Tab | **允许**切换窗口，但遮罩必须仍覆盖在最上层。若被同样声明为置顶的第三方窗口（全屏播放器、录屏工具等）盖住，记为观察项——置顶层级只能保证顺序，无法保证压过所有竞品窗口 |
| A8a | R1 / R3 | 按 Win 单键 | 开始菜单不弹出 |
| A8b | R3 | 按菜单键（VK_APPS） | 已知限制：下层程序会弹出右键菜单，但被置顶遮罩挡住不可见。不算失败 |
| A9 | R1 / R2 | 输入法正在组词时按空格 | 已知限制：会被判为跳过（钩子在按键层拦截，输入法看不到该按键）。休息期间按空格本身即表达「跳过」意图 |
| A10 | 全部 | 点击遮罩本身 / 尝试点击遮罩以外区域 | 焦点不转移；遮罩覆盖整屏（含任务栏），不存在「遮罩以外区域」 |
| A11 | R1 / R2 | 跳过之后立即继续打字 | 按键正常输入到原窗口；仅 A3b 描述的瞬间仍按住的键除外 |

补充：若跳过时用户仍按着跳过键，程序会持续吞掉该键的重复消息，直到收到抬起；若抬起事件丢失（切换安全桌面、远程桌面断连、拔出键盘等），最多 8 秒后强制恢复键盘。

### A11 实测结论（2026-11-14，v1.1.2）

**结论：PASS。R1 与 R2 各跑 3 轮，跳过之后立刻打出的 `abc` 全部放行，无一被吞。**

| 模式 | 轮次 | 跳过后观察到的 keydown | 判定 |
|---|---|---|---|
| R1（StrictMode=1） | 1 / 2 / 3 | `A`、`B`、`C` 三个全部到达 | PASS |
| R2（StrictMode=0） | 1 / 2 / 3 | `A`、`B`、`C` 三个全部到达 | PASS |

同时观测到（属预期，非缺陷）：

- **跳过键本身被吞**：空格按下时 EyeLite 的钩子返回 1，所以下游观察钩子看不到空格的 keydown。这与「空格既用于跳过又被吞」的实现一致，不影响 A11 判定。
- **跳过后第一个按键的时延**：A 的 keydown 出现在跳过时刻之后约 **82ms**（注入本身每键间隔约 40ms），B、C 依次各差约 180ms。整个 `abc` 在约 **450ms** 内完成，无异常延迟。

**方法说明（为什么不是"看目标窗口里出现了 abc"）**

A11 的判据本质是「这个键有没有被 EyeLite 的钩子放行」，所以直接在**钩子链上**观测，比在窗口里看文本更直接。实测确认了三条前提：

1. 多个低级键盘钩子共存时，**后装的先被调用**（链条按安装倒序）。
2. **上游**（后装）钩子吞掉某键后，**下游**（先装）钩子收不到该事件；反向不成立。
3. 于是把观察钩子装在 EyeLite **之前**（成为下游），「观察钩子看到了」即等价于「EyeLite 放行了」。

仪器可信度的自检（每次运行都做）：遮罩期间注入 `xy`，R1 下观察钩子**必须看不到** —— 若看得到，说明观察钩子不在下游，本轮观测作废。

可复现脚本：`tools/a11-case.py`（用法 `python tools/a11-case.py 1` 或 `0`）、`tools/a11-diag-hookchain.py`（上下游双钩子归因）。

**测试环境上踩过的三个坑**（写自动化用例的人会重蹈覆辙，务必记下）：

1. **`SetWindowsHookExW` 的 hinst 必须传真实已加载模块的句柄**。用 `GetModuleHandleW(None)` 会返回 `ERROR_MOD_NOT_FOUND(126)`，钩子**根本装不上** —— 现象是「注入正常但钩子一个事件都收不到」，极易被误判成「环境不支持注入」。本机实测可用：`ctypes.cast(ctypes.WinDLL('user32')._handle, wintypes.HINSTANCE)`。
2. **`SendInput` 在本机返回 0（注入失败）**，`keybd_event` 才真正进入输入队列。两者返回码都是"看起来成功"级的差别，不打印返回值就会错过。
3. **读记事本文本不要用剪贴板**。Win11 新记事本是 XAML 文本岛，`WM_GETTEXT` 恒空；而「Ctrl+A / Ctrl+C 读剪贴板」若读前不清空剪贴板，会读到上一轮的**陈旧值**，把 FAIL 伪装成 PASS —— 本项目上一轮就是这样误判过一次。

## B 组：计时一致性

| ID | 步骤 | 预期 |
|---|---|---|
| B1 | 工作 5 分钟、离开阈值 1 分钟；剩余约 4 分钟时锁屏 3 分钟再解锁 | 剩余时间减少约 **1 分钟**（等于阈值），而不是 3 分钟；解锁后托盘提示「检测到离开，计时已暂停」，动一下鼠标即恢复 |
| B1b | 离开阈值保持默认 3 分钟；剩余约 4 分钟时锁屏 2 分钟 | 阈值未达，照常计时，剩余减少约 2 分钟；托盘不显示暂停态 |
| B1c | 把离开阈值设为 0；锁屏 2 分钟 | 不暂停，照常扣满 2 分钟 |
| B2 | 工作 5 分钟；剩余约 4 分钟时让系统休眠 3 分钟再唤醒 | 剩余时间与休眠前相差不超过数秒，不补算；不出现「唤醒即弹休息」 |
| B2b | 边角：阈值为 0 且休眠前剩余 1 秒 | 唤醒后第一次计时即弹出休息（已知边角，允许） |
| B3 | 休息倒计时中锁屏 1 分钟（休息总长 20 秒） | 休息在锁屏期间照常走完并记为完成（锁屏即人不在屏幕前，视作真实休息）；解锁后遮罩已消失、托盘回到工作倒计时 |
| B3b | 承 B3，注意听 | 结束音在锁屏期间播放，解锁后听不到。**不是缺陷** |
| B4 | 倒计时中把系统时间前/后调 1 小时 | 不崩溃、不跳秒、不出现负数倒计时 |
| B5 | 连续运行跨越系统计时器回绕点（约 49.7 天） | **无法实测**。需连续运行 49.7 天，不安排跑测；结论依据源码：离开时长用无符号减法计算，天然抗回绕。仅在有人报告"运行很多天后离开检测失灵"时才回头看这条 |
| B6 | 休息中拔掉显示器 | 不崩溃、不残留窗体、进程存活 |
| B6b | 承 B6，重新插回显示器 | **下一次**休息时遮罩位置正确（本次休息内不重建，新屏本次可能没有遮罩，允许） |
| B6c | 休息中插上一块新显示器 | 新屏本次没有遮罩；下一次休息正常覆盖 |
| B7 | 休息中点「跳过」或按空格跳过，然后继续工作到下一次到期 | **下一个工作周期按时到期并再次弹出休息**——跳过不得吞掉本轮提醒，也不得出现「跳过一次之后不再提醒」的现象 |
| B7b | 休息中点「推迟」，到推迟时长结束 | 正常弹出休息；推迟不得吞掉提醒 |

| ID | 步骤 | 预期 |
|---|---|---|
| C1a | 前台是提权程序（以管理员运行）时进入休息 | 拆成四项分别判定，见下方「C1a 分项判定表」——**不要合成一个总结论** |
| C1b | UAC 弹窗 / Ctrl+Alt+Del / 锁屏界面 | 屏蔽失效，属操作系统的安全桌面机制，无法拦截；只要求不崩溃、不误判、返回后遮罩仍在、倒计时正确 |
| C2 | 安全软件拦截键盘钩子导致安装失败 | 必须出现**一次**托盘气泡提示，文案按「允许跳过」开关分两种；倒计时仍正常结束休息 |
| C3 | 遮罩弹出时输入法正在组词 | 不抢焦点，未上屏内容不丢失 |

### C1a 分项判定表

准备：以管理员身份启动一个记事本或命令提示符，让它保持焦点，然后等待休息弹出。

| 项 | 观测点 | 通过 | 推翻 |
|---|---|---|---|
| C1a-1 按键拦截 | 在提权窗口中按 `aaaaa`，休息结束后看是否落入 | 未落入 | 落入 → 提权场景下屏蔽失效 |
| C1a-2 遮罩覆盖 | 休息期间观察遮罩是否完整盖住提权窗口 | 完整覆盖 | 被盖住 → 单独记录（与按键拦截无关） |
| C1a-3 跳过可用 | 按裸空格 / 裸 Esc | 正常结束休息 | 无响应 → 单独记录 |
| C1a-4 系统键 | 按 Win 单键 | 开始菜单不弹出 | 弹出 → 单独记录 |

**四项任一失败都必须单独记录，不得合并成一条总结论。** 遮罩是否置顶与按键是否被拦截是两套独立机制，存在「按键拦住了但遮罩被盖住」这种部分成立的情况；合成一条会把它判成整体失败，之后每一次排查都会被这条错误的结论带偏。

**判据来源说明**：「键盘屏蔽不受提权影响」目前是**源码级推论**（低级键盘钩子在原始输入层回调，不注入目标进程，因而不经过窗口消息的完整性级别检查），首次实测之前不得当作既成事实引用。

**无论实测结果如何，都要回看 README 里关于提权场景的表述是否与实测一致**：若实测证明屏蔽生效，说明当前表述低估了自身能力（用户会因为那句话在提权场景下不敢依赖此功能），必须改写；若实测证明失效，则该表述成立，但要把结论来源标注为实测而非推论。两个方向都需要动作，不存在「测完就完事」的情况。

## 观察项纪律

**任何「不应发生 X」的断言都是观察项，不能作为通过判据。** 「没有看到」与「没有测到」无法区分，把它当通过条件会让清单永远变绿。

因此，凡是只能通过「什么都没发生」来验证的行为（例如「某提示不应出现」），一律记为观察项：保留记录、参与人工判断，但不计入通过率。
